# 巡访助手 - 群消息监控 + MuMu多实例巡访

微信群/QQ群消息 与 Excel 名单 → UID 自动识别 → MuMu 多实例自动巡访领礼盒。

## 整体流程

```
微信群 ──┐
         ├──→ 消息监控 → 识别UID(8位) → 主号通道（搜索→点头像→拜访→领礼盒）
QQ群 ────┘
                          ↑
Excel名单 → 小号通道（只查找不领取）→ 发现可领取 → 同步给主号
```

- **主号**（1~N 个）：收到 UID 后执行完整巡访领取流程，多个主号**并行**（每个实例一个线程）
- **小号**（0~N 个）：循环读 Excel，只查找不领取，发现可领取 UID 同步给主号
- 两个通道各自一条串行队列线程：通道内部串行、通道之间并行
- 支持只开 1 个主号、只开 1 个小号、或任意组合

## 一、巡访状态机

```
search     找朋友页 → 点输入框 → 输入UID → 点放大镜搜索
  ↓
results    搜索结果页 → 点头像打开资料弹窗 → 点「拜访」
  ↓
home_gift  看到礼盒气泡 → 连续点击 4~5 次 → 等「选择祝福」面板
home_empty 看到空旗气泡 / 无礼盒 → 只判别不点击 → 回找朋友页
honors     荣誉墙（礼盒已被领完，如"50人已祝福"）→ 回找朋友页
  ↓
choose     选择祝福面板 → 点「选择」
  ↓
claimed    结果页 / 领奖弹窗 → 点「好的」/下方 X → 回找朋友页 → 下一个UID
```

- 模板阈值 + 搜索区域复用 exe 的 `template_specs.json`
- 全流程**轮询等待**（不是固定 sleep）：标志一出现立刻返回
- 每次点击有重试，搜索等结果超时 12s

### 关键实现细节（都是踩过坑修出来的）

| 环节 | 实现方式 |
|------|----------|
| 输入 UID | 必须点输入框本体 (276,559)；点放大镜图标只用于**触发搜索**；回车无效 |
| 清空输入框 | 一次 adb 调用连发 12 个退格键码（原来逐个发 15 次 ≈1.27s，现在 ≈0.08s） |
| 判断搜索结果刷新 | 结果卡区域（头像+名字）24x24 灰度指纹差分，变了就走，最多等 2.5s |
| 判断新搜索是否完成 | 结果卡"停稳"检测（连续两次指纹差 <1.5） |
| 点头像 | 结果卡滑入动画停住 + 搜索后固定等 0.6s（实测搜索后有约 0.7s 输入锁，会吞掉点击）再点 |
| 点击是否被吞 | 整屏指纹（灰度 64x36）差分：**差 <6 = 被吞可再点；差大 = 弹窗已开，绝不再碰头像** |
| 等「拜访」按钮 | **全屏搜索**（位置会随弹窗内容下移，小 ROI 会搜不到） |
| 点「拜访」 | 等按钮**停稳**（连续两次坐标差 <8px，最多 0.6s）再点，按住 130ms（慢实例短按不响应） |
| 进家园 | 看到右下角点赞按钮即判定已进入；主号此时**先手点击礼盒位置** (296,517)，不等气泡识别 |
| 判定礼盒 | 礼盒/空旗气泡位置随镜头移动 → 全屏搜索 + 多尺度；单次点击常不响应 → 连点 4~5 次 |
| return 找朋友页 | 点底部 X → 回结果页；点不到就点主界面右下角好友入口；**不用 Android BACK 键**（游戏内无效，还会把面板关掉） |

三条模板规则（非常重要）：

1. **动画变体**：模板名 `xxx` 会自动附带尝试同名 `xxx_b`。游戏里气泡有星光闪烁/呼吸缩放，
   单张模板跨帧分数会掉到 0.65；做双相位模板后跨帧 10/10 稳定命中。
2. **多尺度匹配**：spec 里 `"scales": [1.0, 0.92, 1.08]` 会按不同比例各匹配一次，命中即返回。
   模板统一按**高度**等比缩放（`scale = height / 1033`），宽高比必须用竖屏版式裁。
3. **空旗只判别不点击**：空旗气泡是"礼盒已被抢完"的证据，看到就直接返回，绝不点（点开是荣誉墙）；
   **只有礼盒气泡才连点 4~5 次**。

## 三、性能（实测优化前后）

| 指标 | 优化前 | 优化后 |
|------|--------|--------|
| 单个 UID 端到端（输入→搜索→点头像→进家园） | ~16.5s | **~14.2s** |
| 清空输入框 | 1.27s | **0.08s** |
| 礼盒匹配（全屏） | 1683ms | **379ms** |
| `detect_state` 全套 | 2984ms | **389ms** |
| 礼盒点击到弹出面板 | 经常点空 | 一次命中 |

提速手段：
- **全屏搜索降采样一半**（`wide=True` 时 ds=0.5，像素减到 1/4，约 4 倍提速，分数影响 <0.01）
- 缩放后的模板**缓存**（按 `(模板名, 缩放比)` 缓存，不重复 resize）
- **命中即返回**（不再把所有尺度/变体跑完取最大值）
- 礼盒优先：礼盒还在就说明弹窗没出，跳过整套 `detect_state`
- 指纹自适应等待替代固定 sleep

> 家园停留时间：进家园后最多等 3s（`home_dwell`），期间每 0.2s 轮询，看到礼盒/空旗/荣誉墙立刻判定返回。
> 主号还有"先手点击"——进家园瞬间镜头就把礼盒移到屏幕中心附近，先点一下再判定，抢礼盒就是拼这一下。

## 四、小号 scan_only 模式

| 小号查找结果 | 行为 | Excel标记 |
|------------|------|----------|
| available（可领取） | 同步 UID 给主号领取 | 标记跳过（**无主号在线时不标记**，保留待重扫） |
| empty（已抢完 / 空旗 / 荣誉墙） | 不同步 | 标记跳过 |
| claimed（已领过） | 不同步 | 标记跳过 |
| not_found（搜索结果多人 = UID 不存在） | 不同步，不计失败 | 标记跳过 |
| error（出错） | 不同步 | 不标记，下次重试 |

> ⚠️ 曾经的 bug：先 `_mark_processed` 再 `_sync_to_main`，同步被自己刚打的标记拦掉 →
> 小号扫到礼盒但永远不推主号。现已改为先同步、成功后再标记。

### UID 有效性判定

搜索结果里**只有 1 个玩家才是正确的**。UID 输错/不存在时游戏停在哪，有两种表现：

| 表现 | 判定方式 | 耗时 |
|------|----------|------|
| 旧行为：弹「请输入正确的玩家名字或数字编号」，推荐列表有多个人 | 统计绿色「申请」按钮连通域数量 ≥2 | ~3.5s |
| **改版后**：停在找朋友页，「可能认识的玩家」下面是**空列表**（幽灵图 + "暂时没有内容"） | `empty_list` 模板命中，连续两帧确认（搜索后等 3s 防误判加载中） | **~3.5s** |

> ⚠️ 没有空列表判定时，错误 UID 会干等 12s 搜索超时、再盲点头像 3 次，
> 一个坏 UID 要卡 ~30s，主号通道后面的任务全部排队"等待中"。

## 五、Excel 名单（不依赖列名）

读取规则：**扫描整张表所有单元格**，用正则提取其中所有 8 位数字，按出现顺序去重。
不看表头、不判列名、不要求放在哪一列。

- 兼容数字单元格（int/float/科学计数）、文本单元格、夹在文字里的 UID（如 `UID:12345678`）
- 忽略日期、布尔、公式报错等其它类型
- 在表右侧维护 `processed` 列，仅用于跨重启跳过，不参与 UID 识别

实测某份名单：608 个非空数字 → 去重后 **458 个有效 UID**。

## 六、多实例与角色

### 自动登记

不需要在 `config.py` 里写死实例。自动检测按以下顺序查找 MuMu 安装目录
（跨机器通用，详见《环境设置指引.md》）：

1. 环境变量 `MUMU_ROOT`（手动指定安装根目录）
2. 项目目录 `mumu_path.txt`（第一行写安装根目录，装在自定义目录时用）
3. Windows 注册表卸载信息（DisplayName 含 MuMu）
4. 常见安装路径 + 全盘扫描（Program Files / LOCALAPPDATA / 各盘符下的 Netease 目录）

找到目录后：

1. 扫 `vms/*/configs/vm_config.json` 拿每个实例 ADB 端口（缺失时用
   `MuMuManager.exe` 官方 CLI 兜底枚举）
2. 生成 IPC 配置、连接 MuMu 原生 SDK
3. **发现几个就登记几个**（第 3、第 4 个模拟器打开就能显示，新增实例默认角色=小号）
4. 新实例默认角色可在面板下拉框改成主号

查找失败时日志会打印完整诊断过程和修复提示；也可运行 `python check_env.py`
或 `python mumu_discover.py` 单独查看。

MuMu 12 多开的 ADB 端口按 **+32** 递增：16384 / 16416 / 16448 …

### 角色持久化

面板上改的主号/小号角色写入 `roles.json`，服务启动时自动恢复（以前重启就全变回默认值）。
当前示例：

```json
{ "instance_1": "main", "instance_2": "worker", "instance_3": "main" }
```

### 横屏防护（三层）

坐标换算基于竖屏 exe 版式，按高度等比缩放。**横屏下所有坐标全部失效**（会乱点开无关菜单、
拜访永远点不到），所以：

1. `visit_one()` 开头：`width > height` 直接报错 `landscape_screen`，拒绝执行
2. 任务层 `_drop_landscape()`：执行前过滤掉横屏实例，日志提示"请转回竖屏"
3. 连接时 `_connect_engine()`：检测到横屏立刻告警

## 八、安装与运行

> 新机器部署请先看《环境设置指引.md》，并运行 `python check_env.py` 自检。

```bash
# 依赖（已配置清华镜像源，文件在 %APPDATA%\pip\pip.ini）
pip install -r requirements.txt

python server.py
```

浏览器打开 `http://localhost:8000`

> **注意：「启动服务」≠「启动监控」。** `server.py` 启动的只是 Web 面板和各执行器的待命状态，
> **总攻监控、消息监控（巡访队列）、Excel 扫描等所有自动化开关都不会自动开启**，
> 必须由用户在面板上手动点击（或调对应 `/api/*/start` 接口）。
> 不要在启动服务时代用户开启任何监控——模拟器画面用户可能正在手动操作。

依赖：`uiautomation, psutil, fastapi, uvicorn, websockets, openpyxl, opencv-python-headless, numpy, python-multipart`

### 前置设置

- **关闭 MuMu 多应用保活**：MuMu 设置 → 高级设置 → 关闭"多应用保活" → 重启模拟器（每个实例都要关）
- **模拟器保持竖屏**（如 1080x1920），横屏会被拒绝执行
- 微信/QQ 窗口不能最小化

## 九、Web 面板

**顶部**：自动检测环境、连接全部 ADB、启动总攻监控、停止全部

**左侧**
1. **连接状态** — 微信/QQ/ADB 状态灯 + 每实例卡片（角色下拉框）+ 检测报告
2. **消息监控** — 启停 + Excel 读取 + 速度选择 + 统计 + 进度条
3. **手动巡访** — 输入 UID、选择目标实例（可选"忽略已处理记录"），走完整领取流程；「只进家园」按钮走轻量通道（进家园领礼盒、领完停在家园、不进队列）
   - 带**进家园记录**列表：进成功过的 UID 不再重复进，可一键清空
4. **消息流** — 实时滚动，UID 高亮，按来源着色（微信/QQ/Excel/手动）
5. **巡访任务列表** — **主号通道 / 小号通道 分两栏显示**，各自 UID 来源/状态/执行结果/统计

**右侧**
1. **模拟器画面** — 每实例独立预览框 + 实时截图（1.5s 刷新，后端线程池抓图 + 缩到宽 600，不阻塞事件循环）
2. **运行日志** — 实时滚动
3. **巡访引擎** — 已初始化的实例与分辨率

> 面板采用**结构签名 + 增量更新**：只有实例列表结构变化才重建 DOM，否则只改文本/颜色。
> 预览图用双缓冲切换。所以不会每隔几秒整屏闪一下。

### 只进家园轻量通道（手动触发）

面板「手动巡访」里的**「只进家园」**按钮：输入 UID 后点它，走独立轻量通道——
「搜索 → 拜访 → 进家园 → 领礼盒 → 选祝福」，**不进主号任务队列**，领完**停在家园**由用户手动退出
（下次触发会自动先返回找朋友页再搜下一个）。

- 记录落盘 `home_visited.json`（保留 500 条，面板实时显示「领到礼盒/空旗/UID 无效」），**失败不记**允许重试
- 进成功过的 UID 再提交不会重复进；面板可「清空进家园记录」重进
- 并发安全：主号队列、小号通道、只进家园共用引擎，`engine_gate.py` 给每个实例一把互斥锁排队

### Excel 名单管理

点「查看名单」弹窗：拖拽上传 xlsx/xlsm/csv/tsv/txt，显示每个 UID 的查找状态
（待查找/可领取/已抢完/已领过/不存在/失败），当前正在查找的高亮，并统计总数/已查找/待查找/可领取。

### 速度选择

| 选项 | 值 | 说明 |
|------|-----|------|
| 快速 | 0.16s | 网络好、加载快 |
| 标准速度 | 0.32s | 默认 |
| 慢速稳定 | 0.65s | 网络差、加载慢 |

控制每步操作之间的等待间隔（轮询类等待不受影响，仍是"看到就走"）。

## 十、排查

### 巡访失败

去看 `debug_caps/visit_fail_<时间>.png` —— 拜访彻底失败（4 次重试都没进家园）时会自动存现场截图，
保留最近 20 张。常见画面：

| 截图显示 | 原因 | 处理 |
|----------|------|------|
| 横屏画面 | 模拟器被转了横屏 | 转回竖屏 |

## 十一、总攻自动参加（海岛夺金）

独立于巡访任务的常驻监控：自动发现群友发起的总攻并参加，与 UID 巡访互不干扰。

### 流程

```
每 3 秒截图，检测地图右下角聊天入口按钮右上角的红点
  ├─ 有红点        → 立即点开聊天页
  └─ 无红点但距上次检查 ≥60 秒 → 兜底也点开聊天页（防漏）
        ↓
聊天页：找所有「我发起了总攻!」卡片 → 点最底部（最新）那张
        ↓
总攻页：直接点底部按钮框（未参与=参加；已参与=灰按钮，点了无副作用）
        ↓
点左下角返回 → 若还在聊天页则点底部 X 关闭；已在地图页则什么都不点
        ↓
每轮开头顺带检测「总攻完成!」结算弹框 → 自动点「确定」
```

### 关键设计（都是踩坑后定下来的）

| 设计 | 原因 |
|------|------|
| 总攻页**不做判断，直接点按钮框** | 曾用「已参与」模板判断是否跳过，误判会漏参加；直接点最可靠 |
| 点**最底部**的卡片 | 聊天记录按时间排序，多张历史卡片时最新一张在最下面 |
| 关闭聊天前先判断是否已在地图 | 地图底部中央的 ✕ 是「退出活动」，误点会一路退回游戏主页 |
| 红点即时 + 60 秒兜底 | 红点偶尔漏检，兜底保证最多 1 分钟必查一次 |
| 参加后 60 秒冷却 | 同一波总攻不反复开关聊天 |
| 自愈 | 连续 60 秒找不到聊天入口（被退出活动）→ 自动点底部导航回到夺金地图 |

## 十二、游戏机制备忘（实测确认）

- 礼盒位置**不固定**，但进家园后镜头会把它移到屏幕中心附近（exe 坐标约 (296,517)）

- Android BACK 键在游戏内基本无效，会乱关面板

## 十四、钓鱼大赛（多实例自动钓鱼）

页面最下方的「钓鱼大赛 · 多实例控制」模块，可对实例 1/2/3 分别触发完整钓鱼流程。

### 引擎架构（`code/fishing_v023/`，v0.2.3）

```
mumu_io.py      MuMu IPC 后台截图(1080x1920) + 触摸输入，不动鼠标不抢焦点
locator.py      多尺度模板定位钓鱼页画布（title/loot/record/congrats 四锚点）
vision.py       纯视觉状态机：READY→WAIT→BITE→QTE→REWARD/RESULT/RECORD/CONTINUE
controller.py   决策防呆：确认制计数、有界重试、QTE 目标预测（速度外推+双边沿判定）
runtime.py      主循环：会话日志（关键帧PNG + session.log + speed.csv）+ 暂停 + 纪录卡事件
bridge.py       子进程入口：stdin 收 stop/pause/resume，stdout 输出 JSON 事件流
```

- 纯图像识别（无 OCR、无内存读取），后台运行，可多实例并行（每实例独立 IPC 连接）
- 状态识别实测定位 score≈0.95，单竿全程 ≈13s（含结算），连续模式 ≈4.5 竿/分

### QTE 两种轮型与慢速兜底

游戏有两种 QTE 轮，识别与策略不同：

- **快速轮**（~190px/s）：速度回归正常估计，预测按下/松开双落点后点击（主流轮型）
- **慢速漂移轮**（大黄区 + 19S 长倒计时，浮标近乎静止）：帧位移低于噪声门限导致速度估计不可用。
  早期版本会因此卡 10~40 秒直到 QTE 超时。现为两级修复：
  1. `Motion.velocity()` 两遍估计：严格门限（快速轮）失败后用宽松门限（帧位移 >0.15px、速度 ≥4px/s）再试
  2. `slow_drift` 兜底：速度持续 1.2s 不可用且浮标稳定停在黄区内（留 12% 边距）→ 直接点击当前位置

### QTE 僵死看门狗（轮型无关的通用兜底）

无论何种原因（识别全失败、黄区解析失败、失误窗口空转等），只要 QTE 持续太久没有
任何点击就强制出手，避免干等到 `qte_timeout`（38s）丢鱼：

- **一级（默认 5s，`FISH_QTE_FALLBACK_IN` 可调）**：游标在黄区内 → 立即点击
- **二级（一级 +2.5s）**：无视识别结果盲点一次强行推进
- 兜底点击按"失误宽限"处理：失败 0.9s 后解锁继续，**不会终止会话**，
  之后每 ~5s 周期性重试直到 QTE 自然结束
- **点击后无反馈宽限**：普通点击落空（游标没进黄区）时游戏同样不结束本轮，
  旧版会直接停止会话；现宽限解锁继续瞄准，连续 2 次仍无任何反馈才停止。
  另有**同区重复轮保护**：大鱼可能要求在同一黄区多次命中，只要识别健康
  （黄区+游标都可见）就持续解锁瞄准、永不误停，由游戏倒计时自然结束本轮
- 优先级保证：正常预测点击（<1s）→ slow_drift（1.2s）→ 看门狗（5s+），互不抢占
- 离线仿真：`_test_qte_fallback.py`（不发真实输入）

### QTE 窄区时机校准（准确率优化）

关键认知：QTE 触点是**固定屏幕位置**（按压条），游戏判定的是**按压时刻鱼是否在
黄区内**——位置瞄准无意义，本质是**按压时机**问题。三实例并行时帧龄+触控传输
延迟造成系统性偏移，宽区容错大看不出来，窄区必丢。策略：

- **宽区（≥65px）**：维持原策略，预测点一进区（留 14% 边距）即尽早点击
- **窄区（<65px）**：等预测按压中点越过（区中心+搜索偏移）即出手，穿越后
  25px 容错带内均可补射（不做 inside() 硬约束，避免发射窗口被压到 ~40ms
  导致帧采不到、看门狗兜底瞎点）
- **同区重试搜索**：点击后无反馈（未命中）→ 偏移序列 0→+12→-12→+26→-26→
  +45→-45 px（≈±0.22s@200px/s），换新黄区后从全局校准值重新开始
- **命中在线学习**：点击后 1.6s 内闪光确认/黄区切换>15px 判定为命中，把该次
  偏移按速度折算成时间校正量 `aim_dt`（EMA 0.45，限 ±0.30s），之后每个黄区
  第一 press 直接用校准时机；识别抖动（±9px）造成的假"新黄区"不会误学
- **同区重试不清运动历史**：游标运动连续，清掉后速度估计要重新积累 3 帧才
  可用，会白白错过 1~2 次发射窗口
- 离线仿真：`_test_qte_nudge.py`（时机搜索+学习闭环）、`_test_qte_center.py`，
  均不发真实输入

### QTE 快速通道（多实例性能优化）

三实例并行时 CPU 互相抢占，QTE 帧率下降导致快速轮脱靶。现 QTE 期间走轻量识别路径：

- 上一帧确认为 QTE 后，跳过全图模板匹配与结算卡检测（~24ms/帧），
  只验证识别条+紫色按钮仍在并做游标/黄区跟踪（~4ms/帧，**约 5 倍提速**）
- 探测不到 QTE（条消失/按钮变色）自动回退完整识别，QTE 结束瞬间即可切回
  RESULT/RECORD 等状态，不漏结算卡
- 离线验证：真实 QTE 帧 probe 与 analyze 结果 4/4 完全一致，非 QTE 帧正确回退

### QTE 人为失误（拟真人节奏）
- 每 **20~30 次** QTE 点击（区间随机）故意失误 1 次，两种样式随机：
  - **抢拍**：游标距黄区前沿 6~30px 时提前按下
  - **松晚**：按下时机正常，按住 60~240ms 拖到游标滑出黄区远端
- 失误后游戏通常**不结束本轮**（同一黄区继续）：脚本 0.9s 宽限后解锁继续正常瞄准；
  若失误导致鱼跑了，也会正常回待机重抛
- 间隔可用环境变量 `FISH_MISS_MIN` / `FISH_MISS_MAX` 覆盖（面板参数即通过它下发）
- 离线仿真：`_test_qte_miss.py`（不发真实输入）

### 撒鱼饵（等级冲 8）

- **逻辑（两段式）**：待机时读取左下角等级徽章（图鉴上方，默认 4，上限 8）和右侧鱼饵包数量；
  开启撒饵模式后，**等级 < 8 且鱼饵 > 0 就撒饵**：先点鱼饵包 → 弹出确认框 →
  识别绿色「打窝」按钮并点击才真正撒饵（弹窗里还有黄色「通知队友」，绝不点错）；
  鱼饵为 0 或等级到 8 自动转为普通钓鱼
- **等级衰减重激活**：打窝等级会随时间衰减（实测 8 级约 10 分钟后掉回 4 级），
  「等级满/鱼饵耗尽」不是永久禁用——每竿回待机时若读到干净数字显示等级 <8 且鱼饵 >0，
  自动重新激活撒饵循环（`bait_reactivate`，同时纠正单帧数字误读导致的错误关闭）
- **数字识别**：`digits.py` 模板匹配（0-9 字形裁自真实截图，白色字形二值化 + IoU 匹配），
  在全分辨率区域裁剪上运行；待机动画/闪光导致识别失败时每 20s 重试、连续 5 次全失败才放弃（读数 3s 内沿用上次成功值）
- **弹窗识别**：`assets/dawo.png` 模板匹配「打窝」按钮（阈值 0.72），
  弹窗残留时（如上次点击中断）直接补点打窝；跨实例门闩挂在打窝点击上（点鱼饵包开弹窗不占排队）
- **跨实例错峰**：三个实例共享 `debug_fishing/data/bait_gate.*` 文件锁排队，
  **任意两次撒饵间隔强制 > 3 秒**，避免一个号连撒、其他号抢不到
- **安全阀**：
  - 面板每实例「🪱 撒鱼饵」复选框，**默认关闭**；运行中勾选/取消即时生效（也会记住待下次启动生效）
  - 环境变量 `FISH_BAIT_DRYRUN=1` 为演练模式：识别与决策照常，**绝不发送真实撒饵点击**（用于测试）
  - 撒饵点击有确认机制：鱼饵计数减少或等级增长才算成功，4.5s 无效重试 1 次后停止（`bait_no_effect`）
- 离线仿真：`_test_bait.py`（决策逻辑 + 门闩竞争，不发真实输入）

### Web 面板钓鱼模块

- 每实例一张卡片：开始 / 暂停(继续) / 停止，实时显示 状态、抛竿数、QTE 数、收鱼数、竿/分、
  **等级 · 鱼饵数**（待机时识别）、**🪱 撒鱼饵开关**
- 全局参数：竿数上限、QTE 失误间隔（min~max）

    加载历史纪录时同样自愈清理（真实连续两条纪录至少隔一整竿，不会误伤）
  - 注意：当前模板不区分个人/团队纪录，纪录卡均会记录（截图可人工分辨）

### 使用前提与排查

- 实例需先点面板「自动检测环境」生成 `mumu-ipc-N.json`（实例 N ↔ `mumu-ipc-{N-1}.json`）
- 对应实例要先进入游戏的钓鱼大赛页面再点开始；运行中切窗口/最小化不影响（后台 IPC）
- **多实例并行**：互斥锁按模拟器实例独立（`_MuMu{index}` 后缀），三个号可同时各跑一个会话；
  同一实例重复启动仍会被拦截
- 暂停期间不发送任何输入；恢复时在途输入自动作废，不会误点
- 撒鱼饵的"等级满/鱼饵耗尽"判断需**连续两个待机帧确认**才永久禁用，防单帧数字误读
- 常见结束原因：`cast_limit` 达到竿数上限正常收尾 / `qte_timeout` QTE 超时 / `no_canvas` 未找到钓鱼页
- 会话证据在 `debug_fishing/data/logs/<时间戳>/`（关键帧 PNG + session.log + speed.csv）
