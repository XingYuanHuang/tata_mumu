# 巡访助手 - 群消息监控 + MuMu多实例巡访

微信群/QQ群消息 与 Excel 名单 → UID 自动识别 → MuMu 多实例自动巡访领礼盒。

## 整体流程

```
微信群 ──┐
         ├──→ 消息监控 → 识别UID(8位) → 主号通道（搜索→点头像→拜访→领礼盒）
QQ群 ────┘
                          ↑
Excel名单 → 小号通道（只查找不领取）→ 发现可领取 → 同步给主号
```

- **主号**（1~N 个）：收到 UID 后执行完整巡访领取流程，多个主号**并行**（每个实例一个线程）
- **小号**（0~N 个）：循环读 Excel，只查找不领取，发现可领取 UID 同步给主号
- 两个通道各自一条串行队列线程：通道内部串行、通道之间并行
- 支持只开 1 个主号、只开 1 个小号、或任意组合

## 一、巡访状态机

```
search     找朋友页 → 点输入框 → 输入UID → 点放大镜搜索
  ↓
results    搜索结果页 → 点头像打开资料弹窗 → 点「拜访」
  ↓
home_gift  看到礼盒气泡 → 连续点击 4~5 次 → 等「选择祝福」面板
home_empty 看到空旗气泡 / 无礼盒 → 只判别不点击 → 回找朋友页
honors     荣誉墙（礼盒已被领完，如"50人已祝福"）→ 回找朋友页
  ↓
choose     选择祝福面板 → 点「选择」
  ↓
claimed    结果页 / 领奖弹窗 → 点「好的」/下方 X → 回找朋友页 → 下一个UID
```

- 模板阈值 + 搜索区域复用 exe 的 `template_specs.json`
- 全流程**轮询等待**（不是固定 sleep）：标志一出现立刻返回
- 每次点击有重试，搜索等结果超时 12s

### 关键实现细节（都是踩过坑修出来的）

| 环节 | 实现方式 |
|------|----------|
| 输入 UID | 必须点输入框本体 (276,559)；点放大镜图标只用于**触发搜索**；回车无效 |
| 清空输入框 | 一次 adb 调用连发 12 个退格键码（原来逐个发 15 次 ≈1.27s，现在 ≈0.08s） |
| 判断搜索结果刷新 | 结果卡区域（头像+名字）24x24 灰度指纹差分，变了就走，最多等 2.5s |
| 判断新搜索是否完成 | 结果卡"停稳"检测（连续两次指纹差 <1.5） |
| 点头像 | 结果卡滑入动画停住 + 搜索后固定等 0.6s（实测搜索后有约 0.7s 输入锁，会吞掉点击）再点 |
| 点击是否被吞 | 整屏指纹（灰度 64x36）差分：**差 <6 = 被吞可再点；差大 = 弹窗已开，绝不再碰头像** |
| 等「拜访」按钮 | **全屏搜索**（位置会随弹窗内容下移，小 ROI 会搜不到） |
| 点「拜访」 | 等按钮**停稳**（连续两次坐标差 <8px，最多 0.6s）再点，按住 130ms（慢实例短按不响应） |
| 进家园 | 看到右下角点赞按钮即判定已进入；主号此时**先手点击礼盒位置** (296,517)，不等气泡识别 |
| 判定礼盒 | 礼盒/空旗气泡位置随镜头移动 → 全屏搜索 + 多尺度；单次点击常不响应 → 连点 4~5 次 |
| return 找朋友页 | 点底部 X → 回结果页；点不到就点主界面右下角好友入口；**不用 Android BACK 键**（游戏内无效，还会把面板关掉） |

三条模板规则（非常重要）：

1. **动画变体**：模板名 `xxx` 会自动附带尝试同名 `xxx_b`。游戏里气泡有星光闪烁/呼吸缩放，
   单张模板跨帧分数会掉到 0.65；做双相位模板后跨帧 10/10 稳定命中。
2. **多尺度匹配**：spec 里 `"scales": [1.0, 0.92, 1.08]` 会按不同比例各匹配一次，命中即返回。
   模板统一按**高度**等比缩放（`scale = height / 1033`），宽高比必须用竖屏版式裁。
3. **空旗只判别不点击**：空旗气泡是"礼盒已被抢完"的证据，看到就直接返回，绝不点（点开是荣誉墙）；
   **只有礼盒气泡才连点 4~5 次**。

## 三、性能（实测优化前后）

| 指标 | 优化前 | 优化后 |
|------|--------|--------|
| 单个 UID 端到端（输入→搜索→点头像→进家园） | ~16.5s | **~14.2s** |
| 清空输入框 | 1.27s | **0.08s** |
| 礼盒匹配（全屏） | 1683ms | **379ms** |
| `detect_state` 全套 | 2984ms | **389ms** |
| 礼盒点击到弹出面板 | 经常点空 | 一次命中 |

提速手段：
- **全屏搜索降采样一半**（`wide=True` 时 ds=0.5，像素减到 1/4，约 4 倍提速，分数影响 <0.01）
- 缩放后的模板**缓存**（按 `(模板名, 缩放比)` 缓存，不重复 resize）
- **命中即返回**（不再把所有尺度/变体跑完取最大值）
- 礼盒优先：礼盒还在就说明弹窗没出，跳过整套 `detect_state`
- 指纹自适应等待替代固定 sleep

> 家园停留时间：进家园后最多等 3s（`home_dwell`），期间每 0.2s 轮询，看到礼盒/空旗/荣誉墙立刻判定返回。
> 主号还有"先手点击"——进家园瞬间镜头就把礼盒移到屏幕中心附近，先点一下再判定，抢礼盒就是拼这一下。

## 四、小号 scan_only 模式

| 小号查找结果 | 行为 | Excel标记 |
|------------|------|----------|
| available（可领取） | 同步 UID 给主号领取 | 标记跳过（**无主号在线时不标记**，保留待重扫） |
| empty（已抢完 / 空旗 / 荣誉墙） | 不同步 | 标记跳过 |
| claimed（已领过） | 不同步 | 标记跳过 |
| not_found（搜索结果多人 = UID 不存在） | 不同步，不计失败 | 标记跳过 |
| error（出错） | 不同步 | 不标记，下次重试 |

> ⚠️ 曾经的 bug：先 `_mark_processed` 再 `_sync_to_main`，同步被自己刚打的标记拦掉 →
> 小号扫到礼盒但永远不推主号。现已改为先同步、成功后再标记。

### UID 有效性判定

搜索结果里**只有 1 个玩家才是正确的**。UID 输错/不存在时游戏停在哪，有两种表现：

| 表现 | 判定方式 | 耗时 |
|------|----------|------|
| 旧行为：弹「请输入正确的玩家名字或数字编号」，推荐列表有多个人 | 统计绿色「申请」按钮连通域数量 ≥2 | ~3.5s |
| **改版后**：停在找朋友页，「可能认识的玩家」下面是**空列表**（幽灵图 + "暂时没有内容"） | `empty_list` 模板命中，连续两帧确认（搜索后等 3s 防误判加载中） | **~3.5s** |

> ⚠️ 没有空列表判定时，错误 UID 会干等 12s 搜索超时、再盲点头像 3 次，
> 一个坏 UID 要卡 ~30s，主号通道后面的任务全部排队"等待中"。

## 五、Excel 名单（不依赖列名）

读取规则：**扫描整张表所有单元格**，用正则提取其中所有 8 位数字，按出现顺序去重。
不看表头、不判列名、不要求放在哪一列。

- 兼容数字单元格（int/float/科学计数）、文本单元格、夹在文字里的 UID（如 `UID:12345678`）
- 忽略日期、布尔、公式报错等其它类型
- 在表右侧维护 `processed` 列，仅用于跨重启跳过，不参与 UID 识别

实测某份名单：608 个非空数字 → 去重后 **458 个有效 UID**。

## 六、多实例与角色

### 自动登记

不需要在 `config.py` 里写死实例：

1. 遍历实际存在的盘符（C~H）查找 MuMu 安装目录，判定依据是三种 adb 布局任一存在：
   `shell/adb.exe`（旧版）、`nx_main/adb.exe`（新版 MuMu 12）、`nx_device/12.0/shell/adb.exe`；
   再以 `vms/` + `nx_main/` 组合兜底
2. 读 `vms/*/configs/vm_config.json` 拿每个实例 ADB 端口
3. 生成 IPC 配置、连接 MuMu 原生 SDK
4. **发现几个就登记几个**（第 3、第 4 个模拟器打开就能显示，新增实例默认角色=小号）
5. 新实例默认角色可在面板下拉框改成主号

adb 路径自动探测顺序（`config.ADB_PATH` 留 `None` 即可，显式配置的路径会先校验存在）：

```
shell/adb.exe → nx_main/adb.exe → nx_device/12.0/shell/adb.exe
→ ProgramFiles / ProgramFiles(x86) / LOCALAPPDATA 安装位 → 系统 PATH
```

> ⚠️ 新版 MuMu 12 **没有 `shell/` 目录**，adb 在 `nx_main\adb.exe`。旧代码只找
> `shell\adb.exe`，会返回一个不存在的路径，直到"输入 UID"那一步才报 `[WinError 2]`，
> 那时巡访任务已经排进队列了。

MuMu 12 多开的 ADB 端口按 **+32** 递增：16384 / 16416 / 16448 …

### 角色持久化

面板上改的主号/小号角色写入 `roles.json`，服务启动时自动恢复（以前重启就全变回默认值）。
当前示例：

```json
{ "instance_1": "main", "instance_2": "worker", "instance_3": "main" }
```

### 横屏防护（三层）

坐标换算基于竖屏 exe 版式，按高度等比缩放。**横屏下所有坐标全部失效**（会乱点开无关菜单、
拜访永远点不到），所以：

1. `visit_one()` 开头：`width > height` 直接报错 `landscape_screen`，拒绝执行
2. 任务层 `_drop_landscape()`：执行前过滤掉横屏实例，日志提示"请转回竖屏"
3. 连接时 `_connect_engine()`：检测到横屏立刻告警

## 八、安装与运行

需要 **Python 3.13（64 位）**。

### 1. 依赖

**最简单：双击 `装依赖.bat`**，它会建 venv、抓轮子、离线安装、验证导入，全程自动。

手动做的话：

```bash
python -m venv .venv
```

> ⚠️ **不要直接 `pip install -r requirements.txt`**。pip 的请求会被宿主按
> **User-Agent 精确拦截**，返回 `403 Forbidden`。换任何源（清华/阿里/腾讯/官方）、
> 清空所有代理变量、`--proxy ""`、`NO_PROXY` 全部无效——因为拦截不看源也不看代理。
>
> 实测对照（同一个 URL，只改 UA）：
>
> | UA | 结果 |
> |---|---|
> | `pip/26.1.2 {...}` | **403** |
> | Python-urllib 默认 | 200 |
> | curl/8.4.0 | 200 |
> | Mozilla/5.0 | 403 |

改用 `_pipfetch.py`（urllib 默认 UA）从清华镜像**直连抓取 cp313/win_amd64 轮子**到 `_wheels/`，再离线安装：

```bash
.venv\Scripts\python.exe _pipfetch.py fastapi starlette pydantic pydantic-core annotated-types ^
  typing-extensions anyio sniffio idna click h11 colorama uvicorn websockets openpyxl ^
  et-xmlfile opencv-python-headless numpy python-multipart uiautomation comtypes psutil

.venv\Scripts\python.exe -m pip install --no-index --find-links _wheels -r requirements.txt
```

若报 `No matching distribution found for xxx`，把 `xxx` 补到第一条命令末尾重跑即可（传递依赖逐层补齐）。
能正常访问 PyPI 的机器直接 `pip install -r requirements.txt` 也可以，`_wheels/` 不必用。

依赖：`uiautomation, psutil, fastapi, uvicorn, websockets, openpyxl, opencv-python-headless, numpy, python-multipart`

### 2. 启动

双击 **`启动服务.bat`**（优先用 `.venv`、自动切到脚本目录、起服务后开浏览器），或：

```bash
.venv\Scripts\python.exe server.py
```

浏览器打开 `http://localhost:8000`。停止用 `停止服务.bat`。

> `server.py` 启动时会把工作目录切到脚本所在目录，所以从计划任务、快捷方式、
> 或者 `python D:\...\server.py` 这种跨目录启动，也能正常找到 `index.html`、`visit_assets`、
> `roles.json`、`uid_list.xlsx`。

### 3. 前置设置

- **关闭多应用保活**（硬性门槛，不是性能问题）：`MuMuIO.__init__` 一开头就检查，开着直接抛
  「后台截图需要关闭模拟器多应用保活」，该实例的巡访引擎创建失败，通道里所有功能都用不了。

  界面：设置 → 高级设置 → 关闭"多应用保活" → 重启实例。

  命令行（**不需要重启**，配置会同步到 `customer_config.json`）。`MuMuManager.exe` 在
  `<安装目录>\nx_main\` 下，默认即 `D:\Program Files\Netease\MuMuPlayer-12.0\nx_main\`：
  ```bash
  cd /d "D:\Program Files\Netease\MuMuPlayer-12.0\nx_main"
  MuMuManager.exe setting -v 0 -k app_keptlive -val false
  MuMuManager.exe setting -v 0 -k app_keptlive        # 读回，应为 false
  ```
  `-v 0` 是实例序号（instance_1 对应 0），多开逐个改。

- **竖屏 1080×1920，且机型必须是手机不是平板**：MuMu 的 `tablet.1`(2560×1440) 和
  `tablet.2`(1920×1080) 是**横屏平板预设**，新建实例默认可能就是平板，结果一启动就被判横屏、
  拒绝巡访。到 MuMu 设置 → 显示 里选手机预设 1080×1920。

  adb 改不了方向：`settings put system user_rotation 0` 对 `SurfaceOrientation` 无效，
  方向由 MuMu 宿主侧控制。只能用界面或 `resolution_mode`（`phone.2`）改，改完重启实例。

  验证看启动日志：`巡访引擎已初始化 (1080x1920)` 才对，出现 `(1920x1080)` 说明还是横的。

- **微信/QQ 窗口不能最小化**（UIAutomation 读不到消息）

## 十、排查

### 巡访失败

去看 `debug_caps/` —— 拜访彻底失败（4 次重试都没进家园）时会自动存现场截图。

现行命名 `{前缀}_{串口}_{0..9}.png`：**每个实例每种前缀固定 10 个槽位循环覆盖**
（`idx % 10`），所以不会无限增长。但早期版本用过时间戳命名
（`visit_fail_20261021_091329.png`），那些文件匹配不到槽位、**永远不会被覆盖**，
积多了需要手工清。常见画面：

| 截图显示 | 原因 | 处理 |
|----------|------|------|
| 横屏画面 | 模拟器被转了横屏 | 转回竖屏 |
| 停在"玩法"菜单 | X 按钮位置与 spec 偏移 | 已改全屏匹配 X（`close`/`ok` 都 wide） |
| 停留在搜索结果页 | 头像点击被输入锁吞掉 | 已加 0.6s 等待 + 指纹判断补点 |
| 停在资料弹窗 | 「拜访」按钮下移/动画中 | 已改全屏匹配 + 等停稳 |

### 总攻不参加

| 现象 | 原因 | 处理 |
|------|------|------|
| 日志里完全没有 `[总攻]` 记录 | 监控没开 | 面板点「启动总攻监控」 |
| 反复"聊天页未打开" | 不在活动地图 / 聊天页没弹出来 | 确认模拟器在夺金地图页 |
| 点了但没参加 | 绿条没点中 | 看日志是否"列表页：点击参与按钮"，重扫会自动补点 |
| 被退回游戏主页 | 误点地图底部 X（旧版 bug） | 已修复；若仍出现看是否手工操作导致 |
| 长时间无动作 | 不在活动地图，等自愈（60秒） | 自愈后会自动回地图；频繁出现请检查为何被退出 |

| 现象 | 说明 |
|------|------|
| 日志"搜索结果有多个玩家，UID xxx 不存在" | UID 无效（游戏弹错误提示 + 推荐多人列表），属正常跳过 |
| 日志"看到空旗气泡（已抢完）" | 该家园礼盒已被领完，正常跳过 |
| 日志"点礼盒后进入荣誉墙" | 礼盒领完（如"50人已祝福"），正常跳过 |
| 日志"暂未推给主号，保留待重扫" | 小号发现礼盒但没有主号在线，下轮 Excel 轮询会重试 |
| 日志"横屏实例跳过巡访" | 该实例是横屏，需转回竖屏 |
| 面板预览卡顿 | 检查是否多个实例同时推送 + 电脑负载 |

## 十一、总攻自动参加（海岛夺金）

独立于巡访任务的常驻监控：自动发现群友发起的总攻并参加，与 UID 巡访互不干扰。

### 流程（2026-11-06 重构：驻留聊天页版）

```
每 3 秒截图，先循环清空「总攻完成!」弹框（可能有多个）
        ↓
页面判定（聊天页优先）：
  ├─ 聊天窗页（驻留态）→ 直接进入监听
  ├─ 总攻页（活动地图）→ 点右下角聊天入口进入聊天窗页
  ├─ 停在总攻详情/列表页 → 立即按返回恢复
  └─ 其他未知页面 → miss 计数，连续约60秒触发自愈
        ↓
聊天窗页：扫描绿色「参与」按钮条（灰按钮天然跳过）
  ├─ 没有 → 继续停留，等下一轮（聊天页自动刷新新消息）
  └─ 有 → 点最底部（最新）一条
        ↓
总攻页（按底部条颜色占比区分形态）：
  ├─ 详情页绿按钮 >25% → 点底部大按钮参加
  ├─ 详情页灰按钮 >25% → 已参与，跳过
  └─ 列表页 → 子循环：扫描右侧按钮列 → 逐个点绿「参与」
     → 上滑一屏 → 重扫；滑动后指纹不变且无新绿 = 到底
        ↓
点左下角返回 → 回总攻页（若落在聊天页则自适应点X）
        ↓
再清一轮「总攻完成!」弹框 → 重新点进聊天窗页继续监听
```

### 两个特殊页面

**1. 总攻列表页（多个总攻发在同一地块）**

点聊天绿条不会进单一总攻页，而是弹出列表：左上角「总攻」横幅，每行左侧白底地块缩略图
（如 `沙丘 (15,10)`）、右侧按钮（绿=可参与 / 灰=已申请·申请中·已过期），底部中央白色 ✕。

现在用**颜色扫描 + 上滑翻页**的子循环处理（不再依赖 `zg_title`/`zg_applied` 模板）：

- 扫描右侧按钮列：绿=参与 → 逐个点击（`0.78w`，按钮带中心 y）；灰 → 天然跳过
- 点击没生效的按钮，重扫时补点
- 本屏点完 → 上滑一屏 → 重扫；滑动前后指纹差 <1.5 = 到底，结束
- 点左下角返回回总攻页

**2. 已过期 / 已抢完的总攻**

聊天里和列表页里不可参与的总攻（「已申请」「申请中」「已过期」）按钮都是灰色，
不满足绿色判据，扫描时天然跳过，无需专门模板识别。

### 关键设计（都是踩坑后定下来的）

| 设计 | 原因 |
|------|------|
| **驻留聊天页**轮询，不靠红点 | 聊天页自动刷新新消息，绿参与条直接可见；省掉"关聊天→回地图→看红点→再开聊天"一圈开销 |
| 聊天页识别用左侧深色频道栏 | 卡片模板已失效（现版匹配不到）；深色占比聊天页 0.57 / 列表页 0.14 / 详情页 0.20 / 地图 0.34，阈值 0.45 干净分离 |
| 参加后 5 秒短冷却 | 等按钮变灰动画结束再重扫，防止同一条绿按钮被连点 |
| 列表页点完上滑 + 指纹判断到底 | 列表可滚动，只点当前屏会漏；滑动前后指纹差 <1.5 = 画面没动 = 到底 |
| 列表页点击后重扫补点 | 单次点击可能不生效，重扫时发现还是绿色就补点（上限 40 次点击 / 12 次翻页防死循环） |
| 弹框循环清空 | 回总攻页可能连续弹多个「总攻完成!」，一次只点一个会残留挡住聊天入口 |
| 返回后自适应判断落点 | 正常返回直达总攻页；若落在聊天页（旧版行为）就点底部X |
| 关闭聊天前先判断是否已在地图 | 地图底部中央的 ✕ 是「退出活动」，误点会一路退回游戏主页 |
| 列表页 / 详情页按底部条颜色区分 | 绝不扫上半屏：详情页上半是实时地图（绿虚线/杀敌toast会误报） |
| 自愈 | 连续 60 秒不在已知页面 → 自动点底部导航回到夺金地图 |

## 十二、游戏机制备忘（实测确认）

- 礼盒位置**不固定**，但进家园后镜头会把它移到屏幕中心附近（exe 坐标约 (296,517)）
- 礼盒被领完的家园，点开礼盒气泡会进入**荣誉墙**（不是领取界面）
- 弹窗有**上滑动画**，按钮一边升一边点会点空
- 搜索结束后有约 **0.7s 输入锁**，期间点头像会被完全吞掉
- 资料弹窗是浮层，顶部搜索栏仍可见 → 不能靠"看到搜索框"判断是否已回到搜索页
- Android BACK 键在游戏内基本无效，会乱关面板

## 十三、技术栈与已知限制

**技术栈**：Python 3.13 + FastAPI + WebSocket / Windows UIAutomation / MuMu 原生 SDK（nemu_* DLL，后台截图不占鼠标）/ OpenCV 模板匹配 / 单页 HTML 前端

**已知限制**
- 仅支持 Windows
- 微信/QQ 窗口不能最小化
- 模拟器必须竖屏；分辨率变化后坐标基准仍按 `height/1033` 等比缩放
- **MuMu 新建实例默认可能是平板预设**（`tablet.1`=2560×1440 / `tablet.2`=1920×1080，都是横屏），
  不手动改成手机 1080×1920 就一启动被判横屏、拒绝巡访
- 巡访模板阈值很紧（0.87~0.89）：720×1280、1440×2560 虽然比例仍是 9:16、坐标计算成立，
  但模板缩放后要过插值，匹配分掉到 0.86 就直接失败。**建议锁定 1080×1920**，
  改高度也别改宽高比；总攻宽容得多（`SCALES` 0.80~1.60、阈值 0.65），能容忍分辨率差异
- 依赖 `MuMu` 原生渲染 SDK（`external_renderer_ipc.dll`）截屏，多应用保活开着会拿不到 surface
- 模板是从实际游戏画面裁的，游戏 UI 大版本更新后可能需要重裁
- 需要真实"有礼盒"的环境才能验证完整领取链路，日常样本多为空旗/已领完
