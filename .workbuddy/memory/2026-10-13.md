## QQ 群聊消息读取打通（「塔塔夺金MVP」群）

### QQNT 的两个关键坑（都已解决）
1. **群聊是独立窗口**，标题就是群名（这里是「塔塔夺金MVP」，129 人群），
   不是 "QQ"。所以不能只找 `Name="QQ"` 的主面板窗口。
   识别方法：桌面顶层窗口里筛 `ClassName=Chrome_WidgetWin_1` + `ProcessId` 对应的
   进程名是 `QQ.exe`/`QQNT.exe`（用 kernel32 `QueryFullProcessImageNameW` 查，
   不能只看类名，否则会混进 Chrome 浏览器）。
2. **后台窗口的 UIA 树是懒加载的**（实测数据）：
   - 窗口在后台 → 整棵树只有 **8 个节点**，没有「消息列表」
   - 调用 `SetActive()` 激活一次 → 立刻变 **320 个节点**，「消息列表」出现
   - **激活一次后就一直保持**（失去前台后仍是 320/311 节点，不会塌回去）
   所以 `QQMonitor` 加了 `auto_activate`：连不上时自动激活一次 QQ 窗口来"点亮"控件树，
   成功后不再抢焦点（`_activated` 标志防止反复激活）。

### QQNT 消息列表的真实结构（和原代码假设完全不同）
- 控件是 **`WindowControl(Name="消息列表")`**，**不是 `ListControl`**（原代码找 ListControl 所以永远读不到）
- 单条消息：`GroupControl(发送者昵称)` + 兄弟 `GroupControl → GroupControl → TextControl(正文)`
- **坑：嵌套层数不稳定** —— 有时 `消息列表→行` 是 1 层，有时 `消息列表→容器→行` 是 2 层。
  写死层数会漏读。最终改成**特征匹配递归**：某节点若「第一个子节点是带名字的 GroupControl
  且存在含 TextControl 的兄弟节点」就认定是一条消息。
- 顺序：DOM 里是**从新到旧**（最新一条在最下面），返回前 `reversed()` 成时间正序。
- 实测可读到 12 条可见消息，发送者/正文都正确。

## 巡访引擎 matchTemplate 崩溃修复（三个叠加 bug）

### 报错
两个实例全部：`cv2.matchTemplate` 断言 `(depth == CV_8U || depth == CV_32F) && type == _templ.type()`。

### 根因（三个独立 bug 叠加）
1. **通道数不匹配**：`mumu_io.decode_pixels()` 返回 `COLOR_RGBA2BGRA` 的 **4 通道 BGRA**，
   而模板是 `imread(IMREAD_COLOR)` 的 3 通道 BGR。matchTemplate 要求 type() 完全一致。
   → 修复：`VisitEngine` 新增 `to_bgr()`，`screenshot()` 和 `match()` 统一归一化成 BGR。
   （顺带修了截图接口 `imencode('.jpg', 4通道)` 的同类隐患。）
2. **visit_assets 里 6 个模板 png 文件名和内容错位**（看了图才确认）：
   - results_title.png 内容是"当前手气最佳"（应为 best_title）；best_title.png 是"搜索结果"（应为 results_title）
   - suggest_title.png 是"选择祝福"（应为 choice_title）；choice_title.png 是"选择"按钮（应为 choose_button）
   - choose_button.png 是"拜访"按钮（应为 visit）；visit.png 是拇指图标（应为 thumb，正好补上 spec 里缺失的 thumb）
   - 重命名后**每个 png 尺寸与 spec box 完全一致**（45x45↔45x45 等），证实对应关系正确。
   - suggest_title（"可能认识的玩家"）现在没有 png 了——它本来就不能作为 results 判定
     （找朋友页面也显示"可能认识的玩家"）。results 判定改用 results_title（"搜索结果"）。
3. **坐标缩放按宽度算错了**：`_scale_box` 用 `width/549=1.99`（x）和 `height/1033=1.86`（y）分开缩放。
   实测全屏多尺度模板匹配：search_icon 最佳缩放 **1.85 ≈ 1920/1033（按高度）**，得分 0.974；
   按 1.99 缩放 ROI 直接把图标（实际在 x=988）排除在 ROI（x≥1026）外。
   → 修复：统一用 `scale = height/1033`。

### 顺带增强
- `match()` ROI 向外扩 25% 余量（≥10px），容忍轻微映射偏差
- 模板大于 ROI 时缩到能放进 ROI（保持宽高比），不再直接 return None（那会让状态判定永远失效）
- `detect_state` 顺序：标题类（best_title→claimed / choice_title→choose / results_title→results）在图标类（gift/search_icon）之前，
